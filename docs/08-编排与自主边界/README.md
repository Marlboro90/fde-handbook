# 第 8 章　编排与自主边界

「上 Agent」经常是一个组织决策，而不是技术决策。这一章给三维判据，让你能说清什么情况下该用工作流；以及一条容易被忽略的设计要点：工具的价值在失败语义。

> 本章收敛：**reality** ｜ 节数：4 ｜ 交付物：编排选型表（L1）

## 本章小节

| 节 | 标题 | 一句话主张 | 判据级 |
| --- | --- | --- | --- |
| 8.1 | 多数「Agent」的正确答案是工作流 | 选 Agent 的前提是「步骤不可预知且失败可承受」，两者缺一不可。 | L1 |
| 8.2 | 工具设计的核心是失败语义 | 工具设计的核心不是能力，是让模型知道失败了以及为什么。 | L1 |
| 8.3 | 自主边界要写进产品 | 写进文档的边界等于没有边界；自主边界必须落在交互里。 | L2 |
| 8.4 | 编排反模式 | 编排的四种反模式几乎都源于同一个动作：用技术结构去弥补需求本身的模糊。 | L1 |
