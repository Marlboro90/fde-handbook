# 第 3 章　从请求到成果

整本书最容易被跳过、也最不该跳过的一章。意图没收敛就往下做，后面所有工作都建在一个没人验证过的前提上——而且不会报错，只会到验收那天一起爆炸。

> 本章收敛：**intent** ｜ 节数：4 ｜ 交付物：成果契约（L2）

## 本章小节

| 节 | 标题 | 一句话主张 | 判据级 |
| --- | --- | --- | --- |
| 3.1 | 请求是解决方案的伪装 | 客户给出的第一个需求，是解决方案伪装成的需求；照单执行等于替客户承担他没想清楚的成本。 | L1 |
| 3.2 | 看变通，不看流程 | 真实痛点不在访谈的回答里，而在员工绕开流程的那些「变通」动作里。 | L1 |
| 3.3 | 成果契约的六个字段 | 成果必须用客户自己的考核语言写，且必须能被非工程师复述。 | L2 |
| 3.4 | 意图熵的放行判据 | 意图熵的收敛判据是「你能否用客户的成果，反驳客户自己的请求」；做不到就还没收敛。 | L2 |
