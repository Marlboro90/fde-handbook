# 术语表

> 本表按 [14.1](../14-术语模板与反模式/01-统一语言是项目启动的第一步.md) 的方法组织：每条写清「它是什么」，也写清「它不是什么」——后者用来解决边界问题。别名与易混项写在定义末尾。
>
> 全书共 56 条主张、14 份模板、20 余条反模式，索引见 [14.3 反模式索引](../14-术语模板与反模式/03-反模式按现象索引.md) 与 [14.2 模板索引](../14-术语模板与反模式/02-模板的价值在字段.md)。

## 一、本书自建概念

| 术语 | 定义 | 出处 |
| --- | --- | --- |
| **五熵模型** | 把客户现场的不确定性分为意图、边界、现实、效果、留存五层，各自有熵源、收敛手段与代理指标 | 1.2 |
| **意图熵** | 客户说不清要什么；说出的第一个需求往往是解决方案的伪装 | 1.2 / 3.x |
| **边界熵** | 范围会自我膨胀；每次「顺手加一个」都不计价 | 1.2 / 4.x |
| **现实熵** | 数据与系统与客户描述不符；权限与网络比预想复杂 | 1.2 / 6.x |
| **效果熵** | 模型输出不确定；「好用」无法量化 | 1.2 / 9.x |
| **留存熵** | 上线后被绕过；客户离不开你 | 1.2 / 11.x |
| **收敛** | 把某层不确定性降到可用判据落地的程度。不是「消灭不确定性」（做不到），也不是「写更多文档」（文档是副产品，不是收敛本身） | 1.1 |
| **放行判据** | 判断「这一层算不算收敛完、能不能进入下一层」的可检验标准。不是里程碑——里程碑回答「什么时候」，判据回答「到什么程度」 | 1.3 |
| **判据卡** | 每节末尾的四字段表格：判据项 / 合格线 / 不合格信号 / 处置动作。不是检查清单——清单回答「做没做」，判据卡回答「做到什么算合格」 | 全书 |
| **交付凭证链** | 十三份交付物构成的有向链，每环是下一环的输入，缺环则后续判断失效 | 4.2 / 全书 |
| **三级判据** | L1 可复现 / L2 可反驳 / L3 可移交，用于标注交付物的完成程度。不是质量分级——它衡量的是「别人能不能验证」，不是「做得好不好」 | 4.2 |
| **反例案** | 同一客户同一团队的失败项目（B 项目，工单自动分派），用于检验模型是否有预测力。不是反面教材——它检验的不是「你该怎么做」，是「这个模型能不能预测失败」 | 1.4 / 9.4 / 12.3 |
| **最小闭环** | 一次能交差的判断，含五个环节：输入、判断、依据、可复核、可回退。少一个就要靠人补，等于没交付 | 4.3 |
| **失败模式** | 一类问题在什么条件下必然发生，四段：触发条件 / 机制 / 后果 / 预防设计。不是需求——需求说「我要什么」，失败模式说「哪里会出错」 | 12.3 |

## 二、最容易被误用的缩写

| 缩写 | 本意 | 常见误读 | 判别方法 |
| --- | --- | --- | --- |
| **FDE** | Forward Deployed Engineer，前沿部署工程师 | Frontend Development Efficiency（前端开发效能）——这是一个真实存在的撞名 | 看交付物：对上线结果负责的是前者，产出内部工程规范的是后者 |
| **FDSE** | Forward Deployed Software Engineer，部分公司对同一角色的内部称谓 | 与 FDE 视为两个岗位 | 看 JD 是否含客户现场与验收责任 |
| **SA** | Solutions Architect，解决方案架构师 | 等同于 FDE | SA 通常对方案负责，FDE 对结果负责 |
| **POC / PoC** | Proof of Concept，概念验证 | 「小范围试用」 | 有毕业标准（时间、指标、数值）的才是验证，否则是试用 |
| **MVD** | Minimum Viable Deployment，最小可行部署（本书用法） | 等同于 MVP | 裁判不同：MVP 由市场判定，MVD 由这个具体客户的具体业务判定 |
| **UAT** | User Acceptance Testing，用户验收测试 | 等同于验收条款 | UAT 是动作，验收条款是标准 |

## 三、交付物名词

| 术语 | 一句话 |
| --- | --- |
| 成果契约 | 一页写清买单者、被考核的成果、痛点持有人、重新框定后的问题、为什么原方案不成立、可观测成功指标 |
| 拒绝清单 | 明确写下「不做什么」以及每条的理由与回落条件 |
| ADR | Architecture Decision Record，一页一决策：背景 / 选项 / 取舍 / 代价 / 复核条件 |
| ROI 结构表 | 只给公式结构，数值由客户提供 |
| 验收条款 | 指标定义 / 测量方法 / 样本量 / 未达标处置，四条缺一不可 |
| 勘察记录 | 数据源分级、接入路径、权限矩阵、对进场三天的预测 |
| 考题集 | 需求的可执行版本，含难例与拒答样本 |
| 双阈值 | 放行线与回滚线，单一分数不足以支撑放行 |
| Go-Live 清单 | 上线前的阻塞项与非阻塞项检查表 |
| 采用度看板 | 周活跃使用人数 / 人工接管率 / 二次主动使用间隔 |
| 交接手册 | 决策路径而非技术细节，验收线是客户能独立改一次 |
| 复制判定表 | 判断哪些该产品化、哪些必须留在现场 |

## 四、避免使用的词

以下词在本书中不出现，因为它们无法被检验：

「赋能」「闭环」「抓手」「顶层设计」「最佳实践」（除非附具体条件）、「业界领先」「一站式」、「保姆级」、「从 0 到 1」（作为口号时）。

如果一句话删掉这些词之后什么都不剩，那它本来就没说任何事。
