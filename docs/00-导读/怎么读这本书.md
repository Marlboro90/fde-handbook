# 怎么读这本书

## 先看一句话

> FDE 交付的不是软件，是不确定性的收敛。

如果你认可这句话，后面 56 节都在展开它。如果不认可，直接去读 [第 1 章](../01-交付的本质是熵减/README.md)——那一章就是为反驳它准备的材料。

## 三个入口

### 入口一：我要转岗（9 周）

适合有 2–5 年开发经验、正在面试或准备面试的工程师。

| 周 | 读什么 | 本周产出 |
| --- | --- | --- |
| 1 | 第 1–2 章 | 五熵自评表 + 能力坐标定位 |
| 2 | 第 3 章 | 对身边一个真实业务做一次影子观察，写成果契约 |
| 3 | 第 4–5 章 | 拒绝清单 + 3 份 ADR + ROI 结构表 |
| 4 | 第 6 章 | 数据分级与勘察记录 |
| 5 | 第 7–8 章 | 跑通一条最小链路，写出编排选型表 |
| 6 | 第 9 章 | 30 条考题集 + 第一版分数 |
| 7 | 第 10–11 章 | Go-Live 清单 + 采用方案 |
| 8 | 第 13 章 | 作品集页 + 5 分钟口述稿 |
| 9 | 补实训线 | 三条线任选一条走完 6 个里程碑 |

**不要跳第 3 章。** 意图不收敛，后面全是空转，而且不会报错。

### 入口三：我是甲方，要会看方案（2 周）

第 1、3、5、9 章精读，配合 [14.3 反模式速查](../14-术语模板与反模式/README.md)。不做动手任务，只做一件事：把第 5.3 的验收条款改写成你自己项目的招标要求。

这本书对甲方读者有一个额外用途：**它能告诉你乙方哪些话是在含糊其辞。** 比如「准确率 95%」——没有测量方法、没有样本量、没有未达标处置，这句话在合同里等于没写。

## 每节怎么用

固定六段，建议按这个顺序读：

1. **本节主张**（30–60 字）—— 先判断你同不同意。不同意就带着反驳读，读不懂就说明这节对你有价值。
2. **现场处境**（200–300 字）—— 一条主线案例里的具体场景。跳过它也能读，但会失去「这个判断在什么情况下成立」的锚点。
3. **判断与做法** —— 主体。
4. **放行判据卡** —— 全节最该抄走的东西。四个字段：判据项 / 合格线 / 不合格信号 / 处置动作。
5. **动手练习** —— 建议真做。看答案不算。
6. **参考与来源** —— 有外部事实才列；写「本节为原创论述」的，表示没有外部依赖。

## 三条实训线

全书有一条主线案例（锦程精工，**虚构的合成客户**，其中的数据与对话均为教学假设，不是调研结果），另有三条并行的实训线。**任选一条走完即可**，不必三条全做。

| 线 | 场景 | 技术重点 |
| --- | --- | --- |
| A 知识助手 | 维保知识检索 + 故障判定辅助 | RAG、引用可追溯、拒答策略 |
| B 工单 Agent | 售后工单分派与跨系统操作 | 工具契约、人在回路、幂等与失败处理 |
| C 限域数据分析 | 售后成本分析问答 | Text-to-SQL、权限感知、数值校验 |

每条线 6 个里程碑，分别落在 3.4 / 4.3 / 6.4 / 7.4（或 8.4）/ 9.4 / 11.3。走完就是一份完整作品集。

## 关于那个反例案

书里有一条反向线索：锦程精工的 B 项目——同一客户、同一团队，为什么失败。

它在 1.4、9.4、12.3 三处回访。作用是检验五熵模型有没有**预测力**，而不只是描述力：B 项目在意图熵阶段就被跳层（客户直接给了方案，团队照做），六周后在效果熵爆炸（无考题，验收靠吵）。

一个只能解释成功的模型是不可信的。如果你读完之后能提前指出 B 项目会死在哪一步，这个模型对你就成立了。
