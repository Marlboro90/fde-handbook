打开一份漂亮的模板，表格线整齐、标题层级分明、颜色协调。填完之后交上去，看起来专业。

然后项目做了半年，发现方向从一开始就错了——而那份模板里，恰好没有一栏问「为什么原方案不成立」。

**模板的全部价值在于它强迫你回答哪些问题。至于长什么样，几乎不重要。**

## 现场

锦程精工的 A 项目，团队用了一份网上找的需求模板，20 页，从「项目背景」到「风险评估」一应俱全，排版专业。

客户很满意：「你们这个文档做得很规范。」

半年后项目出问题，复盘时发现：那份模板里没有一栏问「客户现在是怎么解决这个问题的」。

于是团队从来没有搞清楚，工程师现在到底是翻手册、问同事、还是打电话。他们默认是「翻手册慢」，所以做的是检索加速；而实际上工程师的主要做法是打电话问老师傅——**真正的瓶颈不是找资料慢，是老师傅不在时没人能判断。**

这个信息如果第一周被问出来，方案会完全不同。

**模板不缺页数，缺一个字段。**

## 两种价值，差距很大

模板有两种价值，被严重混为一谈：

| 价值 | 作用 | 谁受益 | 可替代性 |
| --- | --- | --- | --- |
| **格式价值** | 统一排版、显得专业、便于归档 | 提交方、评审方 | 高——换个模板也一样 |
| **字段价值** | 强迫回答那些容易跳过的问题 | 项目本身 | 低——没有替代品 |

格式价值是表面的，字段价值是实质的。

一份模板如果只提供格式，那它和一张白纸加一个样式表的区别不大。而一份好的模板，它的每个字段都对应一个「曾经因为没问而失败」的经验。

**换个说法：模板不是文档的骨架，是提问的清单。**

## 四类字段

同一个模板里的字段，作用分四类。四类齐了，模板才完整：

| 类型 | 作用 | 缺失会导致 | 例 |
| --- | --- | --- | --- |
| **决策型** | 逼你做选择 | 方案含糊，什么都想覆盖 | 「本系统的范围不包括哪些？」 |
| **证据型** | 逼你给依据 | 判断没有支撑，无法复核 | 「这个数字的来源与统计口径」 |
| **边界型** | 逼你说清失效条件 | 判断被无限外推，用在不该用的地方 | 「这个结论在什么情况下不成立？」 |
| **自检型** | 逼你检查自己的产出 | 低级错误带入下游 | 「本节的判据是否可被第三方独立复核？」 |

四类里，**边界型和自检型最常被漏**。

因为决策型和证据型是「做事」需要的，人天然会写；而边界型和自检型是「防错」需要的，人天然会跳过——尤其在赶进度时。

上面那个案例，缺的是「现状描述」这类**证据型**字段（客户现在怎么做的）。而 9.4 那份验收报告缺的是**边界型**（未覆盖范围）和**自检型**（数字怎么复核）。

## 一个检验方法

拿到一份模板，逐个字段问一句：

> **如果没有这一栏，会导致什么具体的失败？**

答得出具体失败的，这个字段该留。答不出来（或者说「显得完整」），那它是装饰。

用这个方法检验上面那份 20 页模板，会发现至少一半的字段可以删——「项目背景」「意义与价值」「预期收益」这些栏，删了不影响任何判断。

而真正该有的「现状是怎么做的」「为什么不继续这么做」，一栏都没有。

## 模板要带反例

这一点比字段本身更容易被忽略。

只给正例的模板，用户不知道自己填错了。因为「填错」通常不是写错字，是**写得对但没说到点上**。

举例，成果契约的「被考核的成果」这一栏：

- 正例：客户售后部的月度报表里，「返修率」这一项会从 8.2% 降到 7% 以下。
- 反例（看起来对但没用）：提升效率、降低对老师傅的依赖、改善响应速度。

第二种写法语法正确、态度积极、也确实是客户想要的方向——但它无法被检验，所以填了等于没填。

**模板里放一个「填错的样子」，比放三个「填对的样子」有用。** 因为人对照正例时容易自我说服（「我这个也差不多」），对照反例时才会警觉（「我这个好像就是这种」）。

| **变更台账** | 4.2 | 变更内容、提出方、计价方式、影响、批准人 | 每次「顺手加一个」 |
| **ADR** | 4.4 | 背景与约束、选项（含「不做」）、决定、代价、复核条件 | 任何不可逆的技术选择 |
| **ROI 结构表** | 5.1 | 六个变量 + 归属（谁控制）+ 假设 | 客户要数字时 |
| **验收条款** | 5.3 | 指标、分母、出题方、判定方式、抽检规则 | 合同或成果契约里 |

| **考题集** | 9.2 | 分层（基础/难例/拒答/回归）+ 三个比例 | 需求阶段，不是开发完成后 |
| **验收报告** | 9.4 | 五段：结论与判据、逐项结果、覆盖与未覆盖、未达成项、复核方式 | 验收前 |
| **降级矩阵** | 10.3 | 依赖 × 失效 → 动作 → 用户看到什么 | 设计阶段 |
| **证据链台账** | 10.4 | 控制项、实现、证据、复核方法 | 有合规要求时 |
| **交接清单** | 11.3 | 六项交接物 + 三条验线 | 项目中期开始，不是最后两周 |
| **失败模式卡** | 12.3 | 触发条件、机制、后果、预防设计 | 项目复盘，向产品回流 |

十四份。注意它们的时间分布：大部分在第 3–6 章（启动阶段）和第 9–11 章（收尾阶段），中间的技术章节几乎没有模板。

这不是巧合——**模板解决的是「判断该在什么时候发生」，而判断主要发生在项目的头和尾。**

## 一份模板该怎么改

拿到一份现成模板（网上找的、公司旧项目留下的），不要直接用。三步：

**第一步，删。** 用上面那个检验方法，把答不出「没有它会失败什么」的字段删掉。

**第二步，加。** 对照四类字段（决策/证据/边界/自检），看缺哪类，补上。特别注意边界型——「这个结论在什么情况下不成立」。

**第三步，配反例。** 每个关键字段配一个「填错的样子」。

三步做完，模板通常比原来短一半，但好用一倍。

## 判据卡

| 判据项 | 合格线 | 不合格信号 | 处置 |
| --- | --- | --- | --- |
| 字段有依据 | 每个字段都能说出「没有它会失败什么」 | 有「项目背景」「意义价值」这类填充栏 | 删掉，模板要短 |
| 四类齐备 | 决策型、证据型、边界型、自检型都有 | 只有决策与证据 | 补边界与自检，这两类最常漏 |
| 带反例 | 关键字段有「填错的样子」 | 只有正例 | 补反例，它比正例有用 |
| 现状被问到 | 有「客户现在是怎么做的」这类字段 | 只问目标不问现状 | 补，这是最容易漏也最致命的一栏 |
| 可被第三方填 | 没参与项目的人能独立填完 | 需要口头解释才懂怎么填 | 加填写说明与例子 |
| 长度克制 | 3 页以内能填完核心部分 | 20 页，一半是装饰 | 砍到抓住判断为止 |

## 动手练习

**第一题（找漏）**

下面是一份「需求确认单」的字段列表。请指出缺了哪几类字段，各举一个具体的失败场景。

> 项目名称 / 客户方对接人 / 业务背景 / 需求描述 / 功能清单 / 预期上线时间 / 预算 / 验收标准

**第二题（设计）**

你要为团队设计一份「项目复盘模板」，只有一页。请写出你会放的字段（不超过八个），并说明每个字段防止哪种失败。

## 参考答案

**第一题**

缺三类，其中两类是致命的：

**1. 缺「证据型」里的现状描述。** 没有「客户现在是怎么解决这个问题的」。

失败场景：团队默认客户是「翻手册慢」，实际是「打电话问老师傅」。做出来的是检索加速，而真正的瓶颈是「老师傅不在时没人能判断」。方案从一开始就错。

**2. 缺「边界型」。** 没有「本系统不包括什么」和「什么情况下这个方案不成立」。

失败场景：范围不断膨胀，每次「顺手加一个」都不计价；或者系统被用到了不适用的场景上（比如拿它回答需要现场检测的问题），出错后无法解释。

**3. 缺「决策型」里的放弃依据。** 「功能清单」是一份清单，但没有说「为什么先做这些、不做那些」。

失败场景：功能清单变成承诺清单，客户逐条对照，少一条就是没做完。而实际上有些条目当时就判断不该做，只是没说。

另外，现有的「验收标准」这一栏也不合格——如果只写一句话（比如「满足业务需求」），它等于没有。需要展开成 5.3 讲的五要素：指标、分母、出题方、判定方式、抽检规则。

**第二题**

模板示例，七个字段：

| 字段 | 防止哪种失败 |
| --- | --- |
| **当初的判断是什么** | 复盘变成事后诸葛。先写下当时的判断与依据，再看结果，否则会不自觉地用结果倒推 |
| **什么信号最早出现** | 把「运气不好」当结论。任何失败都有早期信号，找出来才能提前发现下一次 |
| **当时为什么忽略了这个信号** | 归因到人。多数忽略都有合理原因（那时信息不足、有更紧急的事），找出原因才能改机制 |
| **代价在哪一层显现** | 泛泛地说「项目失败」。按五熵定位，才知道下次在哪一层设卡 |
| **哪个环节本可以不一样** | 复盘流于情绪。要求指出一个具体可改的动作 |
| **我们现在的规则改了吗** | 复盘不落地。没改规则等于没复盘 |
| **如果重来，会在第几天做什么** | 结论太抽象。给出具体的时间点与动作，才可执行 |

七个字段里，第二个和第三个是核心。它们把「结果复盘」变成「过程复盘」——前者只能得出「下次小心」，后者能得出「下次在哪一步停下来」。

第一个字段（当初的判断）必须在项目开始时就记下来，否则复盘时不成立。这也是为什么复盘模板需要配合一个「启动记录」——两者是一对。

## 自检清单

- [ ] 我的模板里每个字段都能说出「没有它会失败什么」
- [ ] 四类字段齐备（决策/证据/边界/自检）
- [ ] 有关键字段的「填错的样子」
- [ ] 有「客户现在是怎么做的」这一栏
- [ ] 没参与的人能独立填完
- [ ] 核心部分三页内能填完
- [ ] 我知道这份模板的每个字段来自哪次失败

> 本节为原创论述。
>
> 关于主张的边界：当模板的用途是「对外交付」而不是「内部对齐」时，格式价值的权重会上升——比如提交给客户的正式方案，排版与结构确实影响专业感。但即便是对外文档，字段仍然是核心：一份排版普通但问到关键问题的方案，比一份精美但回避问题的方案更容易通过评审。
