# FDE 指导手册

![FDE 指导手册](assets/cover/github-clean-1600x900.png)

**前沿部署工程师（Forward Deployed Engineer）的交付方法与判断标准。**

14 章 56 节，一套自建的理论骨架 + 每节一张放行判据卡 + 112 道情境题。写给要把 AI 真正装进客户业务系统、并对结果负责的工程师。

## 这本书在解决什么问题

关于 FDE 的材料已经不少：岗位科普、面试题库、工具清单、商业叙事。它们大多在回答**「这个岗位需要知道什么」**。但真正让人在项目里栽跟头的，几乎都不是知识缺口，而是判断缺口——

- 客户说「我要一个问答机器人」，你照做了，交付时业务方说「这不是我要的」；
- 第 6 周还在加功能，因为每次「顺手加一个」都没计价；
- 验收会上为一个「准确率算不算达标」吵了两小时，因为当初没人把它写成可测条款；
- 系统上线了，日活个位数，但每一步都「按计划完成」了。

这本书回答的是另一个问题：**在这个岗位上，你怎么判断自己做对了。**

## 核心：五熵模型

> FDE 交付的不是软件，是不确定性的收敛。

客户现场的不确定性分五层。每层的熵源不同，用同一套手段去治是无效的；而且**顺序有依赖**——意图没收敛就做边界，边界会建在错误的成果上。

| 层 | 熵源 | 收敛手段 | 可观测代理指标 |
| --- | --- | --- | --- |
| **意图熵** | 客户说不清要什么，第一个需求是解决方案的伪装 | 成果契约 | 客户能否用自己的考核语言复述目标 |
| **边界熵** | 范围自我膨胀，每次「顺手加一个」都不计价 | 冻结线 + 拒绝清单 + ADR | 变更次数 / 变更计价率 |
| **现实熵** | 数据与系统与描述不符 | 勘察与可信度分级 | 勘察预测命中率 |
| **效果熵** | 模型输出不确定，「好用」无法量化 | 考题集 + 双阈值 | 离线分与在线纠错率的偏离度 |
| **留存熵** | 上线后被绕过，客户离不开你 | 采用度指标 + 交接三条验线 | 客户独立修改次数 |

这个模型是可证伪的：任何一次 FDE 事故都应该能落到其中一层。落不进去，模型就该修订——见 [主张质证](.github/ISSUE_TEMPLATE/claim-challenge.yml)。

## 关于案例

全书使用一条合成案例线：**锦程精工**（区域装备制造企业，售后维保为利润中心）。该客户及其所有数据、人物、对话均为教学目的虚构，不对应任何真实企业；文中出现的比例、天数、金额均为示例假设，不是调研结果。

需要外部事实支撑的地方，一律在节末「参考与来源」标注出处与核查日期。

## 每节长什么样

固定六段，56 节一致：

1. **本节主张** —— 一句话，可辩驳
2. **现场处境** —— 一条主线案例里的具体处境，有人、有时间、有代价
3. **判断与做法** —— 为什么这样判断、怎么做、边界在哪
4. **放行判据卡** —— 判据项 / 合格线 / 不合格信号 / 处置动作
5. **动手练习** —— 1–2 题 + 解析 + 自检清单
6. **参考与来源** —— 只列外部事实出处

「主张」保证观点可质证，「判据卡」保证方法可执行。两件事同时做到，才不是资料整理。
