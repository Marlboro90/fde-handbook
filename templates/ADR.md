# ADR-000：决策标题（一句话，动词开头）

> 复制本文件，重命名为 `ADR-<三位序号>-<短标题>.md`。
> 一份 ADR 只记一个决策。多个决策拆多份，不要合并。
> 对应章节：4.4 边界熵的放行判据。

---

## 一、背景与约束

**当时面对的具体问题**（一句话，不超过 50 字）：

**四个必须填的数：**

| 约束 | 数值 | 说明 |
| --- | --- | --- |
| 数据规模 | | 文档数 / 表数 / QPS |
| 性能或延迟要求 | | 首字响应、P95、批处理窗口 |
| 人力 | | 几人、几周 |
| 时间 | | 决策时距上线还有多久 |

> 这四个数是后续「如果……还成立吗」的对照系。缺任何一个，这份 ADR 就不能用来复现决策。
>
> 常见错误：把「客户需要一个知识库」写进这里。那是需求，不是约束。

## 四、代价

三类至少写两类，每类给具体量。

| 类型 | 具体代价 | 量化 |
| --- | --- | --- |
| 性能代价 | 延迟 / 成本上升 | |
| 维护代价 | 复杂度 / 依赖 / 人力占用 | |
| 机会代价 | 放弃了什么，什么情况下会更划算 | |

> 这一栏最常被写空。**写不出代价，通常说明还没想清楚，或者不敢承认。**
> 反例：「实现复杂度有所提升」——无法用于任何判断。
> 正例：「需维护两套索引，文档更新时重建两次；按当前规模预计每周占用半天。」

## 五、复核条件

出现下列任一情况时，重新评估本决策：

- [ ] （数值阈值，如「文档量超过 5,000 份」）
- [ ] （性能阈值，如「P95 延迟超过 3 秒」）
- [ ] （假设失效，如「型号类查询占比低于 5%」）

> 不要写「后续视情况调整」。那是免责声明。
> 复核条件必须是可以被观测到的数值或事件。

## 附：十分钟检验（写完必须做）

找一个**没参与本项目**的同事，只给他这份 ADR，问三个问题：

1. 如果数据量是现在的十倍，这个决策还成立吗？
2. 如果团队只有一个人，你会改哪个选择？
3. 这份记录里，哪一栏最薄？

| 检验项 | 结果 |
| --- | --- |
| 第 1 问答得上 | 是 / 否 |
| 第 2 问答得上 | 是 / 否 |
| 第 3 问指向 | 哪一栏 |
| 结论 | 通过 / 需要补哪一段 |
